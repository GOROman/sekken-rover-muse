# IMU 実機の接続点と、到着後に必要な調整項目

対象: M5Stack IMU Unit（注文 M5-115515、到着見込み 2026-11-10 頃）
この骨格は実機 IMU 未到着を前提に作られており、**実機での動作確認は未実施**。

## 接続点（コード上の差し込み口）

制御ループは `sekken_rover/imu.py` の `ImuSource` インターフェースだけに依存する。

| 実装 | 用途 |
|---|---|
| `SimulatedImuSource` | 物理シミュレーションから姿勢を読む（現在の検証用） |
| `M5StackImuSource` | **実機用スタブ。到着後にここだけを実装する** |

`M5StackImuSource.read()` は未実装の間 `NotImplementedError` を送出する。
実機をつないだら、このメソッドが `ImuSample(t, pitch, pitch_rate)` を
返すように実装すれば、制御・バッテリー・状態機械のコードは無変更で動く。

## 到着後にやること（チェックリスト）

### 1. ハードウェア確認
- [ ] IMU Unit の実チップを確認する（IMU＋磁力計 Unit の世代により搭載チップが異なるため、I2C アドレスとドライバは現物で確定する）
- [ ] RDK X5 との接続方法を決める（Unit の Grove/I2C を X5 側の I2C へ。X5 に直接つながらない場合は M5Stamp 等のブリッジ経由も検討）
- [ ] 取り付け向きを固定する（ロボットの前方向と IMU の軸の対応を写真で記録）

### 2. センサー読み取りの実装
- [ ] `M5StackImuSource` に I2C 読み取りを実装（加速度＋ジャイロ）
- [ ] 軸マッピング: pitch が「前傾 = 正」になるよう符号を合わせる（`imu.py` の約束）
- [ ] 静止時のジャイロバイアス（オフセット）を起動時に数秒測って差し引く
- [ ] 相補フィルタ等で加速度由来の傾きとジャイロ積分を融合し、`pitch` / `pitch_rate` を作る（補助関数 `tilt_from_accel` が使える）
- [ ] サンプリング周期を制御周期 200Hz（5ms）に合わせる。到達しない場合は周期側を見直す

### 3. 制御ゲインの再調整（実機必須）
現在の `PidGains`（Kp=28.0 / Ki=0.6 / Kd=3.2）はシミュレーションモデル
（重心高 0.12m の簡易プラント）に合わせた仮値。実機では以下を順に行う:
- [ ] 実機の重心高・質量を測り、プラント側パラメータの参考にする
- [ ] 台上（車輪を浮かせた状態）で符号と応答方向だけを先に確認する
- [ ] Kp を小さめから上げ、発振し始めたら Kd で抑える。Ki は最後に微調整
- [ ] 転倒保護: 傾き 34 度超でモーター停止（`plant.fallen` 相当）を実機側でも必ず有効化

### 4. バッテリー・帰還まわり
- [ ] 実バッテリーの電圧→残量% の換算を確認し、`BatteryMonitor` のしきい値（低残量 20% / 危険 8%）を実測に合わせる
- [ ] 放電レート・充電レートの実測値を `Robot` のパラメータへ反映
- [ ] ドック接近の最終誘導（マーカー等）は Stage 2 の設計事項。現骨格は「ドック位置 x=0 へ直進して止まる」ところまで

### 5. 検証の進め方
